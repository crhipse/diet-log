# 식단관리

사진과 자유로운 설명으로 먹은 음식을 기록하고, Claude가 음식별 열량과 영양성분을 추정해 주는 모바일 우선 웹앱입니다. 아침·점심·저녁 구분 없이 먹은 시각 순서로 정리됩니다.

## 지금 가능한 것

- 한 기록에 사진 최대 5장과 여러 음식 설명 입력
- 모바일 브라우저에 맞춰 사진을 WebP 또는 JPEG로 자동 압축
- 사진 없이 텍스트만으로 AI 분석
- AI 없이 음식 여러 개와 영양성분 직접 입력
- 음식별 칼로리·탄수화물·단백질·지방 표시
- 당류·나트륨·식이섬유·포화지방도 함께 저장
- AI의 가정과 신뢰도 확인, 숫자 수정, 결과 확인 후 재분석 적용
- 이전 기록 복사
- 분 조정 없이 시 단위로 입력하는 시간순 타임라인
- 새벽 2시를 하루의 시작으로 사용
- 식단·목표·대사량을 분리한 모바일 하단 3탭 메뉴
- 식단·대사량 기록 표시가 있는 월간 달력으로 날짜 이동
- 감량·유지/리컴프·린매스업·벌크업·직접 설정 목표 추천
- 일일 칼로리·단백질 목표와 주간 누적 섭취량 대비 목표량 시각화
- 개인화 TDEE가 충분히 달라지면 자동 변경하지 않고 새 추천 승인 요청
- 별도 대사량 화면에서 날짜별 아침 체중·체지방률·걸음 수 기록
- 일반 공식 또는 체지방률 기반 공식으로 기초대사량(BMR) 계산
- 저장된 신장 수치는 평소 화면과 입력칸에서 숨기고, `신장 변경`을 눌렀을 때만
  기존 값이 채워지지 않은 새 입력칸 표시
- 간편 활동계수와 오늘의 실제 직업·운동을 이용한 활동대사량(TDEE) 추정
- 사무·재택, 서비스·교육, 외근·영업, 현장·운반처럼 서로 다른 직업 활동을
  템플릿으로 저장하고 같은 날에도 여러 활동을 시간별로 조합
- 완료한 식단과 아침 체중이 14일 이상 모이면 유지 칼로리를 개인화하고,
  28일 데이터에서는 더 안정적으로 보정
- LLM 분석용 Markdown 복사, CSV 내려받기
- 식단·대사량·목표 이력이 포함된 가벼운 JSON 백업과 사진 포함 전체 백업·복원
- 홈 화면에 설치할 수 있는 PWA

## 기록과 API 비용은 누구에게 귀속되나요?

서버나 공용 데이터베이스를 사용하지 않습니다. 기록과 압축된 사진은 현재 기기의 현재 브라우저에만 저장되므로, 다른 사람이 자기 휴대폰에서 같은 주소를 열어도 내 기록을 볼 수 없습니다.

예외도 있습니다. 같은 기기와 같은 브라우저 프로필을 함께 사용하면 기록이 보일 수 있고, 브라우저의 사이트 데이터를 지우면 기록도 사라질 수 있습니다. 시크릿 모드는 영구 기록용으로 적합하지 않습니다. 설정에서 JSON 백업을 정기적으로 내려받는 것을 권장합니다. 오랜 기간 기록한 경우에는 크기가 작은 `기록만 빠른 백업`을 먼저 받아두는 편이 안전합니다.

백업을 `병합`하면 같은 ID의 기록 중 수정 시각이 더 최신인 쪽을 유지합니다. 오래된 백업을 불러오더라도 현재 기기의 더 최신인 수정을 덮어쓰지 않습니다. 기록 전용 백업을 병합할 때는 현재 기기의 기존 사진도 유지합니다. `교체`는 확인 후 현재 기록 전체를 백업 내용으로 바꿉니다.

각 사용자는 설정에서 자신의 Anthropic API 키를 입력합니다. 분석 요청은 사용자의 브라우저에서 Anthropic으로 직접 전송되므로 사용량과 비용도 그 키의 소유자에게 발생합니다. API 키는 앱 코드, 백업, CSV, Markdown에 포함되지 않습니다.

저장된 키 원문은 설정 화면에 다시 표시하거나 입력칸에 미리 채우지 않습니다.
키를 바꾸려면 `API 키 변경`을 누른 뒤 새 키를 입력해야 하며, 연결 확인이
성공하면 새 키 입력값을 즉시 비웁니다.

- 기본: 현재 탭을 닫기 전까지만 API 키 보관
- 선택: `이 기기에 기억하기`를 켜면 현재 브라우저에 보관
- 수동 입력: API를 전혀 호출하지 않음

AI 분석을 누른 경우에만 입력한 설명과 선택한 사진이 Anthropic API로 전송됩니다. 영양 추정치는 실제 제품·조리법·양에 따라 크게 달라질 수 있으며 의료 조언이 아닙니다.

대사량 계산, 개인화 학습, 목표 추천과 달성량 계산은 기기 안에서 수식으로
처리하므로 API를 호출하지 않고 토큰 비용도 발생하지 않습니다. 활동대사량,
유지 칼로리와 목표 수치는 입력 자료를 바탕으로 한 추정값이며 의료적
측정값이나 처방이 아닙니다.

GitHub Pages의 `*.github.io` 저장공간은 저장소 경로별이 아니라 계정 도메인 전체에 적용됩니다. 따라서 같은 브라우저에서 `crhipse.github.io` 아래의 다른 웹앱도 기술적으로 이 앱의 저장공간에 접근할 수 있습니다. 다른 프로젝트도 함께 운영한다면 API 키의 `이 기기에 기억`을 끄거나, 배포 단계에서 이 앱만의 전용 도메인을 사용하는 것을 권장합니다. 서로 다른 사람의 휴대폰 사이에서 데이터가 섞인다는 뜻은 아닙니다.

## 로컬에서 실행

Node.js 24 이상과 pnpm 11이 필요합니다.

```bash
pnpm install
pnpm dev
```

검증 명령:

```bash
pnpm test
pnpm build
```

앱에 Anthropic 키가 내장되어 있지 않습니다. 실행 후 설정 화면에서 각자 키를 입력해야 AI 분석을 사용할 수 있습니다.

## GitHub Pages 배포

이 프로젝트는 `crhipse/diet-log` 저장소의 GitHub Pages 주소를 기준으로 빌드됩니다.

1. GitHub에 `diet-log` 저장소를 만듭니다.
2. 이 프로젝트를 `main` 브랜치에 올립니다.
3. 저장소의 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 지정합니다.
4. 포함된 배포 작업이 테스트와 빌드를 통과하면 `https://crhipse.github.io/diet-log/`에 배포됩니다.

저장소에 API 키나 개인 식단 데이터 파일을 올리지 마세요. 배포 작업에는 비밀키가 필요하지 않습니다.

## 데이터 구조 원칙

AI 분석과 수동 입력은 같은 음식 구조로 저장됩니다. 영양소를 모르는 경우 `0`으로 바꾸지 않고 비어 있는 값으로 유지해, 향후 통계에서 “먹지 않음”과 “알 수 없음”을 구분할 수 있습니다. 개인화 대사량 학습에는 칼로리가 모두 입력되고 사용자가 `식단 기록 완료`로 표시한 날만 사용합니다. 백업에는 스키마 버전이 포함되어 이후 영양소나 기능을 추가할 수 있습니다.

추후 후보 기능은 [BACKLOG.md](./BACKLOG.md)에 따로 정리했습니다.
